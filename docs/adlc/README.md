# ADLC document set

This folder is the working home for the project's lifecycle documents. These files are initial drafts and templates: product-specific facts are marked **TBD** until confirmed. Do not treat a placeholder as an approved requirement or decision.

## Suggested sequence

1. `01-planning-and-feasibility.md` — agree on the problem, goals, scope, constraints, and whether the project is feasible.
2. `02-prd-and-project-brief.md` — define users, outcomes, journeys, and MVP boundaries.
3. `03-requirements-and-srs.md` — turn agreed needs into testable functional and quality requirements.
4. `04-glossary-and-domain-model.md` — stabilize important terms and concepts.
5. `05-system-design.md` — propose architecture, components, flows, stack, and deployment.
6. `06-data-design.md` and `07-api-contracts.md` — specify data and integration boundaries.
7. Record material choices in `08-adr-template.md`; use the remaining quality and operations documents as the implementation plan takes shape.

## Status convention

- **Draft**: proposed wording; requires review.
- **TBD**: information is missing.
- **Approved**: explicitly agreed by the project owner.
